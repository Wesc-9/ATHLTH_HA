# ATHLTH Home Assistant v0.6.0 — Consent-controlled Training History

This release adds **real 30/90-day training patterns** to ATHLTH Training
Intelligence and the iPad kiosk while preserving the existing Home Assistant
left sidebar and the v0.5.1 scroll-stability fix.

## New capabilities

- New **30 / 90 days** switchable activity chart, showing actual shared
  workout count, total training minutes and Apple Health distance.
- A new **Consented 90-day workout history** sensor. Summary records are
  aggregated into compact daily values for Lovelace: the user does not have
  to scroll through 90 individual activities.
- The iPad kiosk **Detaljer** view includes the independent
  `custom:athlth-long-trend-card` with accessible period controls.
- The full ATHLTH dashboard includes the history view under
  **Treningsgrunnlaget**, alongside the weekly plan and existing seven-day
  summary. The existing seven-day widget still represents only the ten
  latest received events; the new 30/90 chart has a different,
  clearly disclosed source.
- The ATHLTH iPhone source can optionally export up to 90 HealthKit
  workout summaries whose completion dates are within 90 days. A successful
  history import is limited to activity type, start/end timestamps,
  duration, optional distance and optional activity energy, basic indoor/
  outdoor classification and a stable workout ID.
- No GPS coordinates, routes, raw heart-rate samples, health diagnoses,
  locations or unstructured personal notes are included in historical
  sync messages.
- **Separate opt-in:** History sharing is OFF by default in
  ATHLTH > Home Assistant settings. It only works when both completed-
  workout sharing and history sharing are enabled. Turning it off sends a
  signed clear operation and removes active stored history.
- Signed feature negotiation: `workout_history_v1`. Older Home Assistant
  installations never receive the new event.
- Summary updates are deduplicated by payload fingerprint on the phone.
  A network error does not mark the sync as completed and the next
  legitimate refresh can retry.
- During HealthKit startup the phone does not wipe history based on an
  empty, not-yet-refreshed HealthKit cache.
- The Home Assistant integration caps the dataset at 90 sessions per
  paired installation, validates dates/numbers and rejects arbitrary
  nested fields or forged "measured" distance claims.

## Provenance and important limitations

- **Apple Health is the source**, not a complete ATHLTH workout database.
  A workout recorded only inside ATHLTH and not saved to HealthKit may not
  appear here.
- **Ninety workouts maximum**, selected from the last ninety days. Athletes
  completing more than ninety sessions during the period will see only
  the newest ninety; totals are **not** guaranteed to be all training.
- Distance may originate from GPS, a treadmill estimate, a connected device
  or manual Health entry. The source API does not reliably prove which.
  Each historical distance is therefore marked
  `healthkit_unverified`; the chart labels it explicitly.
- Empty metrics are *unknown*, not zero. The new chart does not fabricate
  splits, 4×4 interval personal records or strength weights.
- Home Assistant history/Recorder and persistent integration storage may
  retain data until history sharing is disabled and, for Recorder,
  the user separately removes recorded historical states. Installing an
  update alone never enables retrospective sharing.
- An iPhone app build containing the new history export is required.
  **Updating HACS alone does not populate the chart.**
- This source release does not upload or trigger TestFlight.

## Installation

1. Update **ATHLTH in HACS to v0.6.0**, then restart Home Assistant.
2. Keep the existing ATHLTH Kiosk dashboard or use the versioned example
   [iPad kiosk YAML](https://github.com/Wesc-9/ATHLTH_HA/blob/main/examples/ipad-kiosk-dashboard.yaml).
   The HA sidebar remains visible. The iPad kiosk option only styles the
   ATHLTH card and is not the unrelated global Kiosk Mode plugin.
3. Upgrade the ATHLTH iPhone app separately once a compatible version is
   available to you.
4. In ATHLTH's Home Assistant settings, enable **Treningshistorikk ·
   90 dager** only if you want to share those summaries, with **Fullførte
   økter** sharing active.
5. Find **Langtidsutvikling** in Training Intelligence or the iPad
   Detaljer view. Switch between 30 and 90 days.
6. Revoke historical sharing to clear the current sensor. Check HA
   Recorder if historical states also need to be purged.

## Validation

Versioned automation requires HACS, Hassfest, privacy scan, frontend
regressions and pytest against supported Home Assistant versions before
publishing the release tag.

Real-world iPhone, Apple Watch and HA app testing, including opt-out,
sync on weak connectivity, iPad rotation and full app cold start, remains
a separate acceptance step.
